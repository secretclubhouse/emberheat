# Matter Docker Build with Headers

This document explains how the Matter Docker build process now copies both libraries and headers.

## Overview

When building Matter libraries using the Docker build process (`make matter-build-docker`), the system now automatically copies:

1. **Compiled libraries** (`.a` files) to `lib/connectedhomeip/<platform>/`
2. **Source headers** and **generated headers** to `third_party/connectedhomeip/`

This allows the thermos-rust project to compile the Matter C++ wrapper without requiring a local Matter SDK build.

## What Gets Copied

### Libraries
- Location: `lib/connectedhomeip/<platform>/`
- Files: All `*.a` static library files from the Matter build
- Examples: `libCHIP.a`, `libnlfaultinjection.a`

### Headers

The following headers are copied to enable wrapper compilation:

#### Source Headers
- **Location**: `third_party/connectedhomeip/src/`
- **Content**: All `.h` header files from Matter's `src/` directory
- **Purpose**: Core Matter SDK headers needed by wrapper code

#### Third-Party Headers
- **nlassert**: `third_party/connectedhomeip/third_party/nlassert/`
- **nlio**: `third_party/connectedhomeip/third_party/nlio/`
- **Content**: All `.h` and `.hpp` files
- **Purpose**: Dependencies required by Matter SDK headers

#### Generated Headers
- **ASN1OID.h**: `third_party/connectedhomeip/src/lib/asn1/ASN1OID.h`
  - Generated by `gen_asn1oid.py`
  - Contains ASN.1 object identifier definitions

- **ZAP Generated Files**: `third_party/connectedhomeip/zap-generated/`
  - Generated during Matter build process
  - Includes `gen_config.h`, `endpoint_config.h`, etc.
  - **Critical**: These files must match the compiled libraries

- **Build Output**: `third_party/connectedhomeip/<build-dir>/gen/`
  - Additional generated headers from the build process

#### Build Configuration
- **Location**: `third_party/connectedhomeip/config/`
- **Content**: Build configuration files from Matter
- **Purpose**: Platform-specific configuration headers

## Usage

### Building with Docker

```bash
# Build libraries and copy headers for your platform
make matter-build-docker

# This runs:
# 1. Docker builds the Matter SDK from source
# 2. Copies compiled libraries to lib/connectedhomeip/<platform>/
# 3. Copies all necessary headers to third_party/connectedhomeip/
```

### Building Thermos-Rust

Once headers and libraries are in place:

```bash
# Build thermos-rust (will use pre-built libraries + headers)
cargo build --release
```

The build system (`build.rs`) will:
1. Detect pre-built libraries in `lib/connectedhomeip/<platform>/`
2. Detect headers in `third_party/connectedhomeip/`
3. Compile the Matter C++ wrapper using these headers
4. Link against the pre-built libraries

## Why Both Libraries AND Headers?

The Matter C++ wrapper (`src/matter/ffi/matter_wrapper.cpp`) includes Matter SDK headers to use the SDK's API. Even though we have pre-built libraries, the **wrapper needs to compile** against the same headers that were used to build those libraries.

### Headers Needed for Compilation
- `<app/server/Server.h>` - Matter server API
- `<setup_payload/QRCodeSetupPayloadGenerator.h>` - QR code generation
- `<lib/core/CHIPError.h>` - Error handling
- Many more...

### Generated Headers are Critical
Generated headers like `zap-generated/gen_config.h` contain:
- Cluster configurations
- Endpoint definitions
- Feature flags

**These must match exactly** with the libraries, or you'll get linking errors or undefined behavior.

## Directory Structure After Build

```
thermos-rust/
├── lib/connectedhomeip/
│   └── linux-arm64/           # or linux-x64, darwin-arm64, etc.
│       ├── libCHIP.a          # ~138 MB
│       └── libnlfaultinjection.a
│
└── third_party/connectedhomeip/
    ├── src/                    # Source headers
    │   ├── app/
    │   ├── lib/
    │   ├── platform/
    │   └── ...
    ├── config/                 # Build configuration
    ├── zap-generated/          # ZAP generated config
    │   ├── gen_config.h
    │   └── endpoint_config.h
    ├── zzz_generated/          # Cluster definitions
    │   └── app-common/
    └── third_party/            # Third-party dependencies
        ├── nlassert/
        └── nlio/
```

## Troubleshooting

### Build fails with "header not found"

If you see errors like:
```
fatal error: zap-generated/gen_config.h: No such file or directory
```

**Solution**: The headers weren't copied correctly. Rebuild with Docker:
```bash
# Clean and rebuild
rm -rf third_party/connectedhomeip/
make matter-build-docker
```

### Linking errors with pre-built libraries

If you see undefined reference errors during linking:
```
undefined reference to `chip::app::Server::Init()'
```

**Possible causes**:
1. Headers don't match the libraries (different Matter version)
2. Missing library files

**Solution**: Rebuild both libraries and headers together:
```bash
rm -rf lib/connectedhomeip/ third_party/connectedhomeip/
make matter-build-docker
```

### QR code is invalid (returns stub format)

If the QR code is `MT:Y.K<hex>` instead of Base38-encoded:

**Check**:
```bash
# Verify headers exist
ls third_party/connectedhomeip/src/setup_payload/

# Verify correct build type
cargo build --release 2>&1 | grep "INFO: Using"
```

Should show:
```
INFO: Using pre-built Matter libraries from lib/connectedhomeip/linux-arm64
INFO: Using Matter headers from third_party/connectedhomeip
```

## Implementation Details

### Docker Build Script Changes

The `scripts/docker-build-matter-internal.sh` was updated to include header copying logic after building libraries.

**Key Changes**:
1. Added `DEST_HEADERS_DIR` variable
2. Used `rsync` to copy headers (preserves directory structure, excludes non-headers)
3. Explicitly generates `ASN1OID.h` using the Python generator
4. Copies ZAP-generated files from build output

### Build System Changes

The `build.rs` was updated to:
1. Check for pre-built libraries in `lib/connectedhomeip/<platform>/`
2. Check for headers in `third_party/connectedhomeip/`
3. Require BOTH to enable full Matter SDK support
4. Add proper include paths for all header directories
